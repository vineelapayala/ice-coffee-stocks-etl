# Clone and Run Guide

This guide explains how to clone, configure, extract the source data, and run the ICE Certified Coffee Stocks ETL pipeline from scratch.

For the complete project architecture, ETL logic, source details, validation strategy, MongoDB design, and implementation details, see [README.md](README.md).

---

## 1. Prerequisites

Install the following:

- Git
- Python 3.13 or compatible Python 3.x version
- Microsoft Edge or Google Chrome

MongoDB Atlas is optional.

Verify Git:

```powershell
git --version
```

Verify Python:

```powershell
python --version
```

---

# 2. Clone the Repository

Open PowerShell and run:

```powershell
git clone https://github.com/vineelapayala/ice-coffee-stocks-etl.git
cd ice-coffee-stocks-etl
```

---

# 3. Create and Activate the Virtual Environment

Create the virtual environment:

```powershell
python -m venv .venv
```

Activate it:

```powershell
.venv\Scripts\Activate.ps1
```

After activation, the terminal should show:

```text
(.venv)
```

### If PowerShell blocks activation

Run:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Then activate again:

```powershell
.venv\Scripts\Activate.ps1
```

---

# 4. Install Dependencies

Upgrade pip:

```powershell
python -m pip install --upgrade pip
```

Install all project dependencies:

```powershell
pip install -r requirements.txt
```

---

# 5. Run the Tests

Run the test suite from the project root:

```powershell
python -m pytest
```

The current project contains 38 tests.

Expected result:

```text
38 passed
```

If the tests fail, resolve the issue before continuing.

---

# 6. Extract Arabica Data

Arabica reports use deterministic XLS URLs, so browser automation is not required.

Run:

```powershell
python src/run_arabica.py
```

The script downloads the available Arabica reports into:

```text
data/raw/arabica/
```

The extractor automatically:

- Iterates through the configured date range.
- Builds the ICE XLS URL.
- Downloads available reports.
- Handles unavailable reports.
- Handles HTTP 429 responses.
- Uses retry and exponential backoff.
- Skips files that already exist.

After the command completes, verify that XLS files exist:

```powershell
Get-ChildItem .\data\raw\arabica\ -Filter *.xls | Select-Object -First 5
```

You should see files similar to:

```text
coffee_cert_stock_20261001.xls
coffee_cert_stock_20260930.xls
...
```

---

# 7. Prepare the Browser for Robusta Discovery

Robusta is different from Arabica.

The Robusta report URLs are dynamically generated by ICE, so the URLs must first be discovered through a browser session.

The project uses **Nodriver** to connect to a browser running with remote debugging enabled.

You must therefore start Microsoft Edge or Google Chrome before running the Robusta discovery script.

## Important

Keep the browser window open while the discovery script is running.

---

# 8. Start Microsoft Edge for Robusta Discovery

### Recommended Windows setup

Open a **new PowerShell window** and run:

```powershell
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
  --remote-debugging-port=9223 `
  --user-data-dir="$env:TEMP\ice-edge-profile" `
  "https://www.ice.com/report/173"
```

This command:

- Starts a separate Edge browser profile.
- Enables remote debugging on port `9223`.
- Opens ICE Report 173 automatically.
- Keeps the browser session separate from your normal Edge profile.

**Do not close this Edge window.**

---

## If Microsoft Edge is installed in another location

The path above is the common Windows installation path.

If that path does not exist, locate your Edge executable and replace the path.

For example:

```powershell
& "C:\Program Files\Microsoft\Edge\Application\msedge.exe" `
  --remote-debugging-port=9223 `
  --user-data-dir="$env:TEMP\ice-edge-profile" `
  "https://www.ice.com/report/173"
```

---

# 9. Verify the Browser Debugging Port

The project expects the browser debugging port to be:

```text
9223
```

With Edge running, open another PowerShell window and run:

```powershell
Test-NetConnection localhost -Port 9223
```

You should see:

```text
TcpTestSucceeded : True
```

If you get:

```text
TcpTestSucceeded : False
```

the browser was not started correctly with remote debugging enabled.

Close the Edge window and start it again using the command from Step 8.

---

# 10. Run Robusta Report Discovery

Keep the Edge window from Step 8 open.

Open another PowerShell window and navigate to the project:

```powershell
cd C:\path\to\ice-coffee-stocks-etl
```

Replace the path with the actual location of your cloned repository.

Activate the virtual environment:

```powershell
.venv\Scripts\Activate.ps1
```

Then run:

```powershell
python src/robusta_discovery.py
```

The discovery process:

1. Connects to the running Edge browser using Nodriver.
2. Interacts with the ICE Report 173 page/session.
3. Captures the ICE Market Data API response.
4. Extracts dynamically generated CSV report URLs.
5. Extracts report dates and filenames.
6. Stores the discovered report metadata.

---

# 11. CAPTCHA During Robusta Discovery

ICE may display a CAPTCHA.

If a CAPTCHA appears:

1. Complete the CAPTCHA manually in the Edge window.
2. Keep Edge open.
3. Allow the discovery script to continue.

The project does **not** attempt to bypass or solve the CAPTCHA.

Manual CAPTCHA completion is therefore part of the Robusta discovery process when ICE requires it.

---

Before running the main pipeline, verify that both source directories contain data.

Check Arabica:

```powershell
(Get-ChildItem .\data\raw\arabica\ -Filter *.xls).Count
```

Check Robusta:

```powershell
(Get-ChildItem .\data\raw\robusta\ -Filter *.csv).Count

Get-ChildItem .\data\raw\robusta_discovery\
```

The resulting structure should look similar to:

```text
data/
└── raw/
    ├── arabica/
    │   ├── coffee_cert_stock_YYYYMMDD.xls
    │   └── ...
    │
    ├── robusta/
    │   ├── Stock_Report_RC_YYYYMMDD_HHMMSS.csv
    │   └── ...
    │
    └── robusta_discovery/
        ├── discovered_reports.json
        └── robusta_api_response.json
```

The exact number of files depends on the extraction period and ICE source availability.

# 15. Run the Complete ETL Pipeline

Once both Arabica and Robusta source data are available, run:

```powershell
python main.py
```

The pipeline will:

1. Discover local Arabica XLS files.
2. Discover local Robusta CSV files.
3. Deduplicate identical Robusta files.
4. Parse Arabica reports.
5. Parse Robusta reports.
6. Validate individual reports.
7. Combine both datasets.
8. Standardize data types.
9. Validate the consolidated dataset.
10. Generate the quality report.
11. Write the consolidated CSV.
12. Load into MongoDB if configured.
13. Print the pipeline summary.

# 17. Optional MongoDB Configuration

MongoDB is optional.

The ETL pipeline can run without MongoDB.

If MongoDB loading is required, create a `.env` file in the project root.

You can create it directly from PowerShell:

```powershell
@"
MONGODB_URI=<your MongoDB connection string>
MONGODB_DATABASE=ice_coffee_stocks
MONGODB_COLLECTION=coffee_stock
"@ | Set-Content .env
```

Then replace:

```text
<your MongoDB connection string>
```

with your actual MongoDB Atlas connection string.

The final `.env` file should look like:

```text
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster>/<database>
MONGODB_DATABASE=ice_coffee_stocks
MONGODB_COLLECTION=coffee_stock
```

Do not commit `.env`.

# 21. Re-running the Extraction

The extraction scripts skip files that already exist.

Therefore, if an extraction is interrupted, you can safely rerun the relevant command.

### Arabica

```powershell
python src/run_arabica.py
```

### Robusta Discovery

Start the Edge debugging session again:

```powershell
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
  --remote-debugging-port=9223 `
  --user-data-dir="$env:TEMP\ice-edge-profile" `
  "https://www.ice.com/report/173"
```

Then, from another PowerShell window:

```powershell
cd C:\path\to\ice-coffee-stocks-etl
.venv\Scripts\Activate.ps1
python src/robusta_discovery.py
```

Complete the CAPTCHA manually if required.

### Robusta

After discovery:

```powershell
python src/run_robusta.py
```

### Complete Pipeline

Finally:

```powershell
python main.py
```

Run:

```powershell
python --version
```

If Python is not recognized, install Python and make sure it is added to PATH.

Restart PowerShell after installation.

Run:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Then:

```powershell
.venv\Scripts\Activate.ps1
```

## Dependency errors

Make sure the virtual environment is active:

```powershell
.venv\Scripts\Activate.ps1
```

Then reinstall:

```powershell
pip install -r requirements.txt
```

---

## Tests fail

Run:

```powershell
python -m pytest
```

If you need more detailed output:

```powershell
python -m pytest -v
```

---

## Edge does not start

Check whether the Edge executable exists:

```powershell
Test-Path "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
```

If the result is:

```text
True
```

use:

```powershell
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
  --remote-debugging-port=9223 `
  --user-data-dir="$env:TEMP\ice-edge-profile" `
  "https://www.ice.com/report/173"
```

If the result is:

```text
False
```

try:

```powershell
Test-Path "C:\Program Files\Microsoft\Edge\Application\msedge.exe"
```

If that returns `True`, use:

```powershell
& "C:\Program Files\Microsoft\Edge\Application\msedge.exe" `
  --remote-debugging-port=9223 `
  --user-data-dir="$env:TEMP\ice-edge-profile" `
  "https://www.ice.com/report/173"
```

---

## Browser debugging connection fails

Run:

```powershell
Test-NetConnection localhost -Port 9223
```

You need:

```text
TcpTestSucceeded : True
```

If it is `False`:

1. Close the Edge window.
2. Start Edge again using the remote-debugging command.
3. Keep Edge open.
4. Run the discovery script again.

---

## Nodriver is not installed

Check:

```powershell
pip show nodriver
```

If it is not found:

```powershell
pip install nodriver
```

Or reinstall all dependencies:

```powershell
pip install -r requirements.txt
```

---

## CAPTCHA appears

Complete the CAPTCHA manually in the Edge window.

Do not close Edge while:

```powershell
python src/robusta_discovery.py
```

is running.

The project does not bypass or automatically solve CAPTCHA challenges.

First verify the browser connection:

```powershell
Test-NetConnection localhost -Port 9223
```

Then verify the discovery script is being run from the project root:

```powershell
Get-Location
```

The path should end with:

```text
ice-coffee-stocks-etl
```

Then run:

```powershell
python src/robusta_discovery.py
```

Verify the output:

```powershell
Get-ChildItem .\data\raw\robusta_discovery\
```

---

## MongoDB connection error

Check that:

- `MONGODB_URI` is correct.
- MongoDB Atlas is available.
- Your IP address is allowed in MongoDB Atlas Network Access.
- The database username is correct.
- The database password is correct.

You can verify that `.env` exists without displaying its contents:

```powershell
Test-Path .env
```
